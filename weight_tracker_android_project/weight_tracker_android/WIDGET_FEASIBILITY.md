# Android 桌面小组件可行性评估（Phase 4）

## 结论

桌面小组件适合后续版本，但当前版本**尚未实现小组件**。目前应用主界面是 Python/Kivy Activity；Android 桌面小组件由系统桌面进程渲染，不能直接复用 Kivy Widget 树。

## 建议的第一版范围

- 展示最新体重和单位（斤/kg），显示数据更新时间。
- 展示近 7 天平均体重及相对上一个 7 天周期的变化。
- 提供“记录体重”快捷入口：点击后打开 App 的体重录入页，而不是在桌面直接修改数据库。
- 提供 2×1 与 4×1 两种尺寸，采用原生 RemoteViews 的文字/按钮/简单背景，不在小组件中加载体型照片或复杂折线图。

## 技术与隐私前提

1. 需要原生 Android `AppWidgetProvider`、`RemoteViews`、`AppWidgetManager` 更新逻辑，并在 AndroidManifest 中注册 receiver；Python/Kivy 页面自身无法注册一个可直接由桌面加载的布局。
2. 小组件只应读取应用本机 SQLite 的只读快照。建议由 App 将最新值写入经过原子替换的缓存文件/偏好，然后由 receiver 更新 RemoteViews，避免桌面刷新时与数据库写入竞争。
3. 点击操作需通过明确的 `PendingIntent` 深链进入对应页面；不得在多个 widget 实例间共享错误的日期或目标记录 ID。
4. 覆盖安装、重启、应用升级、数据库恢复、单位切换后要刷新所有已放置的小组件；卸载后小组件由系统移除。
5. 不请求网络权限，不创建服务器，也不把体重或身体照片发往外部服务。通知/锁屏展示内容需考虑共享设备隐私。

## 为什么暂缓

第三阶段新建了饮食、力量训练、围度和报告数据结构，第一、二阶段的真实 Android 文件选择器/备份恢复尚需设备回归。小组件依赖原生 Java 和 Manifest 集成，若在当前数据路径与真机行为尚未稳定时并行开发，会增加构建与生命周期风险。建议先通过核心回归门槛，再单独建立一个小范围的 widget 原生模块，并给各 Android API 版本做打包测试。

## 验收门槛

- 冷启动/强制停止后，小组件不显示损坏数据或旧单位。
- 每次新增/编辑/删除体重、切换单位或恢复备份后，显示值和“最近更新”时间正确。
- 重启手机后小组件仍存在并能刷新。
- 快捷入口打开正确页面，返回桌面后不启动多个重复 Activity。
- 断网运行，不依赖后端或账号登录。
