# Android 真机回归清单（P0/P1 + 照片浏览性能）

每次 GitHub Actions 生成 APK 后，记录 APK 对应的 commit SHA、手机型号、Android 版本、可用存储空间和测试结果。先用应用内“完整备份”保存当前数据；升级安装时不要先卸载旧版。

## A. 安装与升级兼容
- [ ] 覆盖安装到已有版本，启动成功，无闪退。
- [ ] 旧体重记录、备注、设置、健身打卡和照片仍存在。
- [ ] 首次启动后 `body_photos.thumbnail_path` 自动迁移，无清库或重复迁移异常。
- [ ] 冷启动、切后台再返回、强制停止后重开均正常。

## B. 核心数据与重复操作
- [ ] 新增、编辑、移入回收站、恢复、永久删除记录。
- [ ] 快速重复点击保存/导入/备份，操作不会重复提交或同时运行多个重任务。
- [ ] 导入同一份 CSV 两次，第二次只报告重复跳过，不产生重复记录。
- [ ] CSV 缺列、日期错误、非法体重会显示行级错误；数据库写入错误时本批次回滚。

## C. 完整备份与恢复
- [ ] 完整备份 ZIP 包含数据库、原图、缩略图，文件大小非零。
- [ ] 通过 Android 系统文件选择器选择备份 ZIP，恢复记录、设置、打卡和照片。
- [ ] 恢复前自动生成保护备份；恢复完成后回到页面能看到最新数据。
- [ ] 选择非 ZIP、损坏 ZIP、缺少数据库或缺少引用原图的 ZIP，恢复失败且现有数据不变。
- [ ] 恢复时模拟/观察低存储空间，提示失败，重启后原数据仍可打开。

## D. Android 系统文件选择器与 CSV
- [ ] “导入 CSV”能打开 Android 文件选择器，可从下载目录/云盘选择文件。
- [ ] 选择 CSV 后即使系统返回 `content://` URI，也能导入，不要求用户手动复制到应用目录。
- [ ] 取消选择不改变数据；选择无法读取的文件会显示错误。
- [ ] 大 CSV 导入期间 UI 仍可响应，结束后记录列表与统计刷新。

## E. 新版体型照片浏览与性能
- [ ] 主照片区域只有一个持久的主图组件；普通切换不创建/销毁整组页面。
- [ ] 轻划即可切换：不需要长按，不需要等待 0.5 秒；水平手势不会明显阻断外层垂直滚动。
- [ ] 上一张/下一张按钮与缩略图点击能立即更新日期、序号和选中状态。
- [ ] 已预加载的相邻照片切换时不出现明显空白/闪烁；未加载图片显示短暂提示且主界面仍可操作。
- [ ] 缩略图时间线横向滚动正常；100、500 张照片时只创建可见的缩略图视图，不创建全量控件。
- [ ] 前后对比模式可分别切换两边照片、交换前后，并能返回浏览模式。
- [ ] 旧记录没有缩略图时，查看会在后台生成缩略图；生成失败不删除原图或照片记录。
- [ ] 快速连续浏览 20/100/500 张照片，再退回日历并重新进入体型页；没有明显卡死，当前索引和顺序正确。
- [ ] 删除照片前备份失败时照片和索引都不删除；删除成功后缩略图时间线同步更新。
- [ ] 执行完整备份恢复后，浏览与对比模式显示恢复后的图片（不是相同路径缓存的旧纹理）。

## F. 启动耗时与日志
- [ ] 冷启动、热启动各测试 5 次；记录手机型号、Android 版本、可用空间和 APK commit SHA。
- [ ] 从 `adb logcat` 中可检索 `[PERF]`，至少包含 `app_import_complete`、`font_registration_complete`、`startup_storage_ready`、`startup_first_screen_ready`、`home_summary_query_complete`、`trend_query_and_aggregate_complete`。
- [ ] 启动期间先显示轻量初始化页；数据库初始化、首页统计、趋势数据查询在后台执行，控件更新只在 UI 线程进行。
- [ ] Android 系统字体可用时优先使用系统中文字形；中文录入和设置页没有方框字/缺字。
- [ ] 和修改前基线对比冷启动、首屏可交互时间及连续滑动体验；仅当真机结果有改善才判定通过。

## G. 系统 UI / 无障碍 / 权限
- [ ] 返回键：弹窗、文件选择器返回、各主页面行为合理，不意外退出或重复打开选择器。
- [ ] 输入体重/备注时键盘不会永久遮住保存按钮；隐藏键盘后布局恢复。
- [ ] 状态栏、导航栏、刘海/挖孔区域无关键控件遮挡。
- [ ] 至少在一台低密度与一台高密度设备或模拟器上检查布局。
- [ ] 系统字体放大到 1.3×/1.5×，文字可读且主要按钮仍可操作。
- [ ] 用户取消文件选择或拒绝相关权限后，应用不闪退，可重新尝试。

## I. 第一、二阶段新增的数据正确性与安全回归

> 本节需要安装本轮新构建的 APK 后人工执行。Python 自动化测试不等同于 Android UI / 文件系统真机测试；尚未执行的项目应保留为“未测”，不要预填“通过”。

### I-1. 趋势图、原始记录与 BMI
- [ ] 同一天录入 131、132、180 斤三条记录；趋势图当天只显示每日平均点，点击该点后必须列出 3 条原始记录，逐个选择后编辑，确认只修改被选择的记录。
- [ ] 在图表数值开关开/关后检查标签即时显示/隐藏；标签与折线点使用同一套坐标，图表日期间距按真实日期差而非记录序号计算。
- [ ] 设置身高 170 cm、最近记录 131 斤，当前 BMI 应约为 22.7。切换到更早的统计范围后，“当前 BMI”仍由全局最新记录计算，不应退回使用历史范围末条记录。
- [ ] 切换 BMI 模式后，图表标题、纵轴单位、标签、均值/最高/最低值单位一起切换；变化项应明确显示为日均变化，目标体重线只在体重模式显示。
- [ ] 没有身高时尝试启用 BMI，应提示先设置身高且保持选项关闭；单条记录及所有点体重相同的图表应有可见的纵轴范围和数据点。
- [ ] 选择过去的日期查看历史范围时，统计卡片应与所选范围一致；“当前 BMI”仍表示当前最新测量，页面标题与单位不得互相矛盾。

### I-2. 照片缩略图时间线与失败恢复
- [ ] 添加至少 2 张图片后离开再进入体型页；时间线应显示卡片、日期和预览，不应整条留白。点缩略图、上一张/下一张及轻划的当前日期和选中状态一致。
- [ ] 测试一张没有缩略图但原图存在的记录；卡片先显示“生成预览中”，Android 后台修复完成后显示缩略图。
- [ ] 将一张缩略图替换为 0 字节或无效图片、保留原图；时间线应显示“预览失败”，自动尝试从原图生成缩略图，失败时不删除原图或数据库条目，并保留“重试预览”入口。
- [ ] 原图也缺失时，时间线应明确显示“原图缺失”，不能无限显示“生成预览中”。
- [ ] 在缩略图生成过程中立刻恢复另一份备份或连续切页；旧任务不能覆盖恢复后的文件、指向错误照片或卡死列表。

### I-3. 备份预览、兼容性和恢复
- [ ] 创建完整备份并通过 Android 系统“保存”选择器导出到 Downloads/文档目录；确认可在应用外看到 ZIP。仅存在应用内部的备份会随卸载/清除应用数据而丢失。
- [ ] 重新选择刚导出的 ZIP，确认预览显示文件大小、体重记录数量及日期范围、照片数量、训练打卡天数、可用空间与预计峰值空间。
- [ ] 在恢复确认框按“取消，不覆盖”，确认数据库、设置、打卡、照片均未变化。
- [ ] 确认覆盖恢复后，检查身高、目标体重、统计范围、BMI/数值标签开关、历史记录、日历打卡和照片时间线均来自备份；恢复完成后不应残留旧缩略图纹理或旧设置状态。
- [ ] 使用旧版备份（没有 `thumbnail_path`、没有回收站/训练表或旧的 `daily_activity` 缺少 `workout` 列）确认兼容迁移成功且原有记录保留。
- [ ] 选择损坏 ZIP、缺少 `weight_tracker.db`、缺少被数据库引用的原图、含路径穿越成员或 0 字节原图的备份；应在覆盖前失败并说明原因，当前数据保持不变。
- [ ] 选择数据库中含越界缩略图路径（如 `body_photo_thumbnails/../other.jpg`）的备份，预览阶段应拒绝，不等到真正覆盖恢复时才报错。
- [ ] 模拟空间不足：预览应显示预计峰值空间与当前可用空间，不足时禁用确认；即使预览之后空间变化，真正恢复时也要重新检查，失败不得损坏当前数据。

### I-4. 输入与 CSV
- [ ] 保存/修改体重时测试未来日期、5 斤、5000 斤、身高 30 cm/300 cm、目标体重 5000 斤；明显异常值应当在保存前被拒绝并说明范围。
- [ ] 合法的边界值、正常小数和备注应正确保存。历史记录编辑到未来日期时，弹窗应在关闭之前明确报错。
- [ ] 导入相同 CSV 两次，第二次应报告重复跳过；`Z` 或带 UTC offset 的时间先标准化到设备本地时间后再去重。
- [ ] 混合有效、重复、未来时间、非法体重的数据文件；用户应看到“部分导入”、新增/跳过/失败数量和失败行号，失败行不能混入数据库；数据库级失败则应整批回滚。
- [ ] 导入 `YYYY/MM/DD HH:MM`、`YYYY年M月D日 HH:MM` 及只有日期的 CSV；应按明确规则规范化；含糊的 `03/04/2026` 需作为失败行提示，不应猜测月/日顺序。
- [ ] 对 CSV 导入、CSV 导出、完整备份导出、完整备份恢复分别打开系统文件选择器后按取消；不得误启动操作、覆盖当前数据或弹出错误堆栈。

### I-5. 卸载、清除应用数据与 Android 系统备份
- [ ] 测试前先用“完整备份”将 ZIP 保存到应用外部（Downloads/文档/用户选择的位置），并检查该文件确实可以重新读取。不能只依赖应用内部备份文件。
- [ ] 记录当前 `buildozer.spec` 的 `android.allow_backup = True`。系统自动备份/恢复行为取决于 Android 设置、账户、厂商 ROM 和平台版本；记录测试设备是否启用系统备份，不能把“本机数据库”理解为系统绝不会备份数据。
- [ ] 在测试设备上执行“设置 → 应用 → 存储 → 清除数据”，再启动应用，观察 Android 系统是否自动恢复；随后使用外部 ZIP 手动恢复并逐项核对数据。
- [ ] 在测试设备上卸载并重新安装同一版本 APK，确认应用内部数据不再可见/是否由系统恢复；从应用外部 ZIP 手动恢复后检查记录、照片、设置与打卡。
- [ ] 分别记录系统备份开启和关闭时的行为。若产品要求严格不通过 Android 系统备份传输数据，再单独评审是否改为 `android.allow_backup = False`；本轮没有擅自更改该既有产品设置。

## J. 第三阶段：饮食与热量记录
- [ ] 在指定日期添加早餐/午餐/晚餐/加餐，填写食物名、份量、每 100g 热量与三大营养素；核对总量按 `份量/100 × 每100g` 计算。
- [ ] 添加自定义食物后，重新打开添加记录窗口，常用食物列表中应出现该食物；选择食物后每 100g 营养素应正确填充。
- [ ] 编辑既有食物记录，确认编辑框反算的每 100g 值与原记录一致，保存后总热量/营养素不被重复乘算。
- [ ] 检查不同日期的日志只显示所选日期数据；修改日期后条目应从旧日期移到新日期。
- [ ] 删除饮食条目后点击“撤销删除”，条目恢复且当日热量和营养素汇总同步恢复；不撤销则保持删除状态。
- [ ] 测试份量为 0、负数、异常高热量、未来时间、空食物名与无效日期；应明确提示且不写入脏数据。

## K. 第三阶段：结构化力量训练
- [ ] 添加力量训练，记录动作、组数、次数、负重、时长和备注；添加成功后该日期自动显示训练打卡。
- [ ] 添加有氧训练（组数/次数为 0、时长大于 0），应允许保存；组数、次数、时长和负重均为 0 时应拒绝保存。
- [ ] 编辑训练日期后，日志列表与相关日历刷新；删除后执行撤销，训练项目与打卡显示恢复。
- [ ] 周报和月报的训练项目数、训练日期数、打卡天数和训练总时长与记录逐项核对。
- [ ] 连续保存/编辑同一动作多条记录，不应覆盖其他记录；负重单位明确为 kg，且不得因体重单位切换而改变。

## L. 第三阶段：本机提醒
- [ ] 启用每日称重、补记饮食和训练提醒，拒绝通知权限时 App 不闪退，并提示用户检查系统通知权限。
- [ ] 用未来几分钟的测试时间验证：App 运行时，到达提醒时间且当天未完成相应记录，应发出通知；当天已有记录/打卡则不应提醒。
- [ ] 检查同一个提醒在同一天不会重复发送；更改提醒时间后使用新时间。
- [ ] 当前实现属于 App 运行/恢复时检查的本机提醒。强行停止、系统杀进程或设备重启后的准时触发**不作为当前版本已支持能力**，不要据此判定通过；如要可靠后台提醒，需后续开发原生 AlarmManager/Receiver 并单独验证。

## M. 第三阶段：身体围度、目标与照片日期
- [ ] 添加腰围、臀围、胸围、体脂率中的任意一项，其他项留空；保存后单位正确，编辑/删除/撤销的值保持一致。
- [ ] 所有身体指标都留空、体脂率超过限制、围度明显不合理、测量日期晚于今天时，保存应被拒绝。
- [ ] 修改体型照片归属日期后，日历照片计数、当天照片过滤、时间线排序一起更新；不应移动、重压缩或删除原图。
- [ ] 目标体重设定、清除和单位切换后，个人页目标值与目标进度使用同一个规范存储值，不发生斤/kg 翻倍。

## N. 第三/四阶段：单位切换、报告和扩展数据导出
- [ ] 在有历史记录时从斤切换到 kg，首页、统计、趋势图坐标/标签、快捷按钮、目标体重、7 日均值和周/月报告全部使用 kg；切回斤后恢复正确值。
- [ ] 切换单位时若首页录入框已输入数值，应将未保存草稿按旧单位转换到新单位一次；数据库原始值不应变化。
- [ ] 生成本周和本月报告，核对起止日期、体重平均、日均变化、7 日平均、热量、蛋白质、训练、围度和照片数量；没有数据时应显示空/记录不足而不是异常数值。
- [ ] 在 Android 分享菜单选择一个目标应用发送报告，确认文本含单位和本机数据提示；取消分享不会改变记录。
- [ ] “导出全部健康数据 ZIP”应包含体重、饮食、食物目录、训练、身体测量、日历打卡、设置、回收站、照片索引和照片原图；空数据表仍应有表头。
- [ ] 将导出的 ZIP 保存到应用外部位置，使用系统压缩工具验证 ZIP 可打开；缺少原图时应明确失败，不得生成看似完整的导出。

## O. 第四阶段：输入、滚动、撤销和可读性
- [ ] 在小屏手机/模拟器上打开身体测量、饮食和训练弹窗，键盘出现时滚动到最后一个字段仍能看到保存/取消操作。
- [ ] 设置身高/目标体重时输入非法字符或极端值，应通过输入过滤及存储层验证拒绝；留空目标体重应能按设计清除目标。
- [ ] 各日志删除后立即显示撤销入口；分别测试撤销/不撤销，确认汇总和日历状态正确。
- [ ] 检查数据加载中、加载失败、空记录、导出进行中/成功/失败的状态提示，不应只有空白页面。
- [ ] 系统字体 1.3×/1.5×、键盘弹出、横向较短视窗和滚动较长列表下，主要操作按钮可见且不会被固定容器裁切。
- [ ] 确认设置页的斤/kg 切换只影响显示与输入边界，SQLite 中仍以 `斤` 作为向后兼容的规范体重存储单位。

## P. 第四阶段：桌面小组件范围

## J. 第三、四阶段：饮食、训练、提醒、报告和单位回归

> 以下为安装本轮新 APK 后的设备验收项。尚未在设备上执行的项目必须保留为“未测”。

### J-1. 日志与营养计算
- [ ] 在选定日期添加一条食物：每 100 g 热量 380 kcal，份量 50 g，蛋白质 13 g、碳水 68 g、脂肪 7 g；汇总应显示约 190 kcal、蛋白质 6.5 g、碳水 34 g、脂肪 3.5 g。
- [ ] 选择已保存自定义食物后检查营养字段回填；重新启动应用后该食物仍在本地列表。
- [ ] 添加、编辑、删除饮食条目并点击“撤销删除”；验证原记录只恢复一次且当日汇总准确变化。
- [ ] 同一天录入至少 5 条饮食记录和 5 条训练记录；所有条目均可滚动看到，卡片不会遮住其他模块或吞掉后续记录。
- [ ] 将日志日期切换到另一天，查看加载状态、空状态和记录日期；快速连续切换日期时，旧的查询结果不能覆盖最新选择。

### J-2. 结构化训练与身体围度
- [ ] 新增深蹲 4 组 × 10 次、负重 50 kg、时长 35 分钟，保存后训练日志可显示完整数值，日历训练状态同步为已完成。
- [ ] 编辑、删除并撤销训练记录；体重记录不应被误删，日历状态应与剩余训练/打卡数据相符。
- [ ] 录入腰围/臀围/胸围/体脂率，编辑后检查当日列表和报告；非法日期、体脂率超界、所有指标都为空时应显示可理解错误。
- [ ] 编辑体型照片日期，确认日历照片计数和时间线顺序刷新，照片原始文件保持不变；取消编辑不应修改日期。

### J-3. 7 日平均、目标进度及周/月报告
- [ ] 同一天录入多次体重、其他日期录入单次体重；7 日平均应先算每日平均值，再对有记录日期求均值，未记录日期不虚构数据。
- [ ] 设置目标体重，核对目标进度为起始记录到当前体重相对目标的估算，进度限制在 0–100%；数据不足时显示原因。
- [ ] 在周末和月末分别生成周报/月报，确认统计范围、周/月体重趋势、热量、训练、身体指标和照片数量只来自对应统计期（目标进度除外，它按全历史计算并在文案说明）。
- [ ] Android 点击“分享报告”应打开系统分享选择器；选择任一分享目标并取消返回，应用应保持可用。报告中不得泄露应用内部绝对路径。

### J-4. 斤/kg 切换
- [ ] 在“我的”页面切换“斤”与“kg”，检查首页输入单位、统计标题、图表纵轴、目标体重、回收站文案、7 日平均与报告均使用一致单位。
- [ ] 数据库/旧版 CSV 仍以“斤”保存；在两种单位之间来回切换后，历史记录值不变。
- [ ] 在首页输入一个尚未保存的重量后切换单位，草稿应按同一实际重量换算，不得把原数值解释成另一单位。
- [ ] 导出的 `weight_records.csv` 标头含 `weight_jin`，确认单位约定在数据 ZIP 的 `README.txt` 里解释。

### J-5. 全部健康数据 ZIP 导出
- [ ] 先添加体重、饮食、自定义食物、训练、身体围度、打卡和至少一张照片，然后执行“导出全部健康数据 ZIP”。
- [ ] 在 Android 保存选择器选择 Downloads 或其他外部文档位置，确认文件保存成功，并能从系统文件管理器打开 ZIP。
- [ ] ZIP 应包含 `weight_records.csv`、`food_logs.csv`、`food_catalog.csv`、`strength_logs.csv`、`body_measurements.csv`、`daily_activity.csv`、`settings.csv`、`recycle_bin.csv`、`photo_index.csv`、`photos/` 和 `README.txt`。
- [ ] 检查 `photo_index.csv` 的每个索引路径在压缩包中都存在；若数据库引用的原图缺失，导出应报错而非声称完成。
- [ ] 模拟可用空间不足，导出应在创建大量临时文件之前拒绝；取消外部保存选择器不会改变数据库，应用内部保留包的提示要清楚。
- [ ] 确认这个 ZIP 是可读数据交换包，不应把它误当作应用内完整备份直接执行恢复。

### J-6. 本机提醒与通知权限
- [ ] 在 Android 13+ 上启用任意提醒，按系统提示授予通知权限；拒绝权限时应用不闪退，并明确说明通知未获授权。
- [ ] 将测试提醒时间设为当前时间后的 1–4 分钟，保持 App 在前台或后台但进程存活，确认最多每天触发一次。
- [ ] 如果今天已经记录体重/饮食/训练，符合条件的提醒应不再发送。
- [ ] 明确记录当前实现的限制：**App 被强行停止、进程被系统终止或设备重启后不保证按时提醒**。不能将这些后台场景标记为通过；正式支持需另行开发原生闹钟接收器和重启恢复。

### J-7. 字体、窄屏、撤销与加载反馈
- [ ] 使用较窄设备、系统字体 1.3× / 1.5×，检查日志输入弹窗、保存/取消按钮、周/月报告长文本和新增导航项没有遮挡。
- [ ] 大量记录加载和报告生成期间，尝试滚动/切换页面，UI 仍能响应；旧日期结果不覆盖当前日期。
- [ ] 饮食/训练/身体指标删除后，在撤销弹窗点击撤销，数据和汇总准确恢复；点击知道了后则不自动恢复。
- [ ] 在低端设备测试切换页面和打开报告，不应在 UI 线程同步执行全历史数据压缩。

### J-8. 小组件范围
