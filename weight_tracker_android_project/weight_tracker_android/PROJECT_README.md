# 体重追踪助手 Android 完整工程（第一至第四阶段）

这是第一至第四阶段合并后的完整项目，不是增量补丁。项目保留现有 **Python + Kivy + SQLite + Buildozer + python-for-android** 技术栈、中文字体、原有页面、完整备份/恢复流程及 GitHub Actions 工作流。当前代码不是 Flet 工程；没有为了新增功能切换技术栈。

## 第一、二阶段：数据正确性与本地数据保护

- 图表聚合点先打开当天原始记录选择器，避免编辑时误改当天最后一条记录。
- BMI/体重模式同步标题、单位与标签；当前 BMI 使用最新记录。
- 照片时间线加载/失败状态、坏缩略图重建、日期编辑及切页缓存处理。
- 完整备份恢复前检查内容、原图路径、数据库兼容性与预计空间；恢复后重新读取设置和刷新缓存。
- 对体重、身高、目标和日期做基础校验；CSV 时间戳标准化、重复判断及部分导入结果清晰反馈。

## 第三阶段：减脂记录

- 新增“日志”页：按份量计算每日饮食热量和蛋白质/碳水/脂肪，支持本地自定义食物、编辑及撤销删除。
- 结构化训练日志：动作、组数、次数、负重 kg、时长和备注，记录后同步训练日历。
- 身体围度/体脂率记录和编辑，体型照片可更改日期。
- 7 日平均体重、目标进度、周/月报告及 Android 分享。
- “导出全部健康数据 ZIP”：体重、饮食、自定义食物、训练、身体测量、打卡、设置、回收站、照片索引和原图；该 ZIP 为数据交换包，不替代 App 内完整备份格式。

## 第四阶段：易用性与生态评估

- “斤 / kg”显示单位切换；数据库仍以“斤”规范存储，切换不会重写历史数据。
- 日志读取和报告计算放后台线程；长列表动态扩展；重要删除支持撤销；输入和异常状态提示有所加强。
- 主屏幕小组件已有设计可行性文档，但本轮未实现原生 Widget。
- 本机提醒在 App 运行或恢复时检查；App 被强行停止或系统终止进程后，不保证准时触发。要做可靠后台提醒，需要另行开发并验证原生定时接收器。

详细功能与已知限制见 `PHASE3_PHASE4_IMPLEMENTATION_README.md`、`PHASE1_PHASE2_FIXES_README.md` 和 `WIDGET_FEASIBILITY.md`。

## 本机验证

```bash
python -m compileall -q app.py main.py storage.py services ui tests
python -W error::ResourceWarning -m unittest discover -s tests -v
```

当前本机结果：**93 项自动化测试通过**。自动化测试包括数据层、单位换算、报告、完整数据 ZIP、旧库迁移和源码回归检查；不代表 Android 上的 Kivy 控件、通知、文件选择器和分享弹窗已经通过真机验收。

## Android 构建与后续验收

使用 `.github/workflows/build-apk.yml` 里的 `workflow_dispatch` 手动触发构建。当前环境没有可用的 Android SDK/NDK 与真机，本轮未构建 APK，也没有推送到 GitHub。构建成功后按 `tests/DEVICE_REGRESSION.md` 的 J 节逐项验收。

## 安全与隐私提示

- 数据默认保存在本地应用目录；卸载或清除应用数据可能导致应用私有数据丢失。重要备份应保存到应用之外。
- 当前 `android.allow_backup = True` 保持不变，Android 系统自动备份/恢复行为取决于设备设置与平台版本。
- 饮食营养值取决于用户输入；本地报告为生活记录汇总，不是医疗诊断。
